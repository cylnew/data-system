[0] 项目：基于 MongoDB 的问卷系统开发
[1] 一、项目目标
[2] 本项目要求开发一个简化版的在线问卷系统，功能类似于“问卷星”或 Google Forms。
[3] 系统应允许注册用户创建问卷，并通过URL分发问卷，其他用户可以填写问卷，系统可以统计问卷结果。
[4] 本项目重点考察：
[5] MongoDB 数据库设计能力
[6] 后端程序设计能力
[7] 数据结构与业务逻辑建模能力
[8] 条件逻辑与跳转逻辑的实现能力
[9] 使用 AI 编程工具的能力与规范
[10] 本项目不要求复杂界面，可以使用简单网页。
[11] 评分重点：
[12] 数据库设计 + 后端逻辑 + 文档质量 + AI使用过程说明
[14] 二、项目说明
[15] 本课程项目将模拟真实互联网应用开发的过程。
在实际的软件开发中，用户需求往往不是一次性确定的，而是会随着使用过程不断增加和变化。开发者通常需要在已有系统的基础上进行修改和扩展，而不是每次都重新设计和实现整个系统。
[16] 为了让大家体验这种真实的软件开发过程，本项目分为 两个阶段 完成。
[18] 第一阶段：根据初始需求完成系统设计与实现
[19] 在第一阶段会提供一份初始用户需求说明。
[20] 同学需要根据这份需求：
[21] 进行系统设计
[22] 完成数据库设计
[23] 实现前后端程序
[24] 完成必要的测试
[25] 编写项目文档
[26] 提交完整的项目报告
[27] 整个过程尽可能利用AI编程工具完成。
[28] 第一阶段提交的内容参见“七、提交内容”。
[29] 第一阶段的成果将作为第二阶段的基础。
[31] 第二阶段：根据用户需求变更对系统进行修改与扩展
[32] 在第一阶段提交完成之后，教师会发布一份新的用户需求变更说明。
[33] 该需求变更模拟真实应用中的情况，例如：
[34] 用户提出新的功能要求
[35] 原有功能需要扩展
[36] 原有设计无法满足新的使用方式
[37] 数据需要以新的方式组织和统计
[38] 在第二阶段，同学需要：
[39] 在第一阶段系统的基础上进行修改和扩展
[40] 根据新的需求调整数据库设计
[41] 修改程序实现
[42] 保证旧功能仍然可用（除非需求明确要求改变）
[43] 完成新的测试
[44] 再次提交完整的项目报告
[45] 整个过程也尽可能利用AI编程工具完成。
[47] 重要要求：不得推倒重做
[48] 第二阶段 不允许丢弃第一阶段的成果重新实现。
[49] 必须满足以下要求：
[50] 必须在第一阶段代码基础上修改
[51] 不得重新设计一个完全新的系统替代原系统
[52] 不得删除第一阶段的主要功能
[53] 必须保留第一阶段的核心结构，并进行合理扩展
[54] 在最终报告中必须说明：
[55] 第一阶段的设计是什么
[56] 新需求带来了哪些问题
[57] 为什么需要修改原设计
[58] 修改了哪些部分
[59] 数据结构如何变化
[60] 程序如何调整
[61] 是否遇到兼容性问题
[62] 如何保证旧功能仍然可用
[63] 即需要清楚记录整个修改过程。
[65] 为什么分成两个阶段
[66] 本项目的目标不是实现一个功能最多的系统，而是让同学体验：
[67] 用户需求不确定
[68] 需求会不断变化
[69] 数据结构需要调整
[70] 系统需要迭代升级
[71] 旧数据必须保留
[72] 旧功能不能随意删除
[73] 这些都是实际互联网应用开发中的常见情况。
[74] 通过两个阶段的开发，希望同学能够理解：
[75] 软件系统不是一次设计完成的，而是在不断变化的需求中逐步演化的。
[77] 三、技术要求
[78] 须满足：
[79] 后端数据库：MongoDB
[80] 编程语言：不限（Python / Node.js / Java / Go 等均可）
[81] 后端框架：不限
[82] 前端：不限，可非常简单
[83] 可以使用 AI 编程工具（ChatGPT / Copilot / Claude / Cursor 等）
[84] 须满足：
[85] 所有数据存储在 MongoDB 中
[86] 不允许使用关系数据库
[87] 不允许用现成问卷系统框架
[89] 四、MongoDB 设计要求（重点）
[90] 建议：
[91] 勿将所有数据存在一个集合
[92] 谨慎使用冗余设计
[93] 勿把逻辑写死在代码
[94] 须说明：
[95] 为什么这样设计
[96] 为什么不用关系数据库结构
[97] 为什么适合 MongoDB
[99] 五、AI 编程要求（重要）
[100] 本项目鼓励使用 AI。如果不借助AI，工作量将大大增加。
[101] 但必须记录 AI 使用过程。
[102] 必须提交：
[103] 5.1 AI 使用日志
[104] 需要说明：
[105] 使用了什么工具
[106] 使用了什么提示词
[107] 得到了什么代码
[108] 是否修改
[109] 修改了什么

得到用户表结构

增加validation字段
[112] 必须真实记录。
[114] 5.2 AI 使用说明
[115] 需要在最终报告中总结：
[116] AI帮了什么
[117] AI做错了什么
[118] 自己改了什么
[119] 自己设计了什么
[120] 评分时会看。

[176] 初始用户需求
[177] 一、用户账号功能
[178] 系统需要支持用户注册和登录。
[179] 用户希望能够：
[180] 注册账号
[181] 登录账号
[182] 使用自己的账号创建问卷
[183] 查看自己创建的问卷
[184] 查看问卷的统计结果
[185] 每个用户至少需要有：
[186] 用户名
[187] 密码
[188] 注册时间
[189] 用户登录后，应只能看到自己创建的问卷。
[191] 二、问卷创建与管理
[192] 用户希望能够创建问卷。
[193] 创建问卷时可以填写：
[194] 问卷标题
[195] 问卷说明
[196] 是否允许匿名填写
[197] 用户希望能够：
[198] 查看自己创建的问卷列表
[199] 发布问卷
[200] 设置问卷截止时间
[201] 关闭问卷
[202] 每个问卷都应该有一个可以访问的链接，例如：
[203] /survey/xxxxxx
[204] 用户可以把这个链接发给别人，让别人填写问卷。
[205] 填写问卷的人需要先登录。
[207] 三、问卷中的题目
[208] 一个问卷可以包含多个题目。
[209] 用户希望在问卷中添加不同类型的问题。
[210] 系统至少需要支持以下三种题型。
[212] 1. 单选题
[213] 示例：
[214] 你的性别
[215] 男
[216] 女
[217] 其他
[218] 用户希望能够：
[219] 设置选项
[220] 设置是否必须回答
[221] 如果是必答题，填写问卷时必须选择。
[223] 2. 多选题
[224] 示例：
[225] 你喜欢的水果
[226] 苹果
[227] 香蕉
[228] 西瓜
[229] 葡萄
[230] 用户希望可以限制选择数量，例如：
[231] 至少选择 2 个
[232] 最多选择 3 个
[233] 必须选择 2 个
[234] 系统在填写时需要检查是否符合要求。
[236] 3. 填空题
[237] 填空题可以是文字或数字。
[238] 用户希望可以创建：
[239] 文本填空
[240] 数字填空
[241] 对于文本填空，希望可以限制：
[242] 最少输入多少字
[243] 最多输入多少字
[244] 对于数字填空，希望可以限制：
[245] 最小值
[246] 最大值
[247] 是否必须是整数
[248] 例如：
[249] 年龄：必须为整数，且在0~120之间
[250] 手机号：必须为整数
[251] 填写时系统应检查是否合法。
[253] 四、题目跳转功能
[254] 用户希望问卷可以根据回答情况跳转到不同题目。
[255] 例如：
[256] 如果第1题选 A → 跳到第5题
如果第1题选 B → 跳到第3题
[257] 用户希望可以设置：
[258] 根据单选结果跳转
[259] 根据多选结果跳转
[260] 根据数字填空内容跳转
[261] 填写问卷时，系统应自动跳到对应题目。
[262] 用户不希望跳转写死在程序里，而是可以在问卷中设置。
[264] 五、填写问卷
[265] 填写问卷的人可以通过问卷链接进入问卷。
[266] 填写时希望：
[267] 按顺序回答问题
[268] 根据规则跳转
[269] 如果填写不符合要求，系统提示错误
[270] 填写完成后可以提交
[271] 每次填写都应该被保存。
[272] 系统需要支持：
[273] 多人同时填写
[274] 匿名填写
[275] 同一个人填写多次（如果允许）
[277] 六、查看统计结果
[278] 创建问卷的人希望可以查看统计结果。
[279] 统计结果至少包括：
[280] 单选题
[281] 每个选项有多少人选择
[282] 总共有多少人回答
[283] 多选题
[284] 每个选项被选择多少次
[285] 填空题
[286] 可以查看所有填写内容
[287] 如果是数字，可以查看平均值
[288] 用户希望能够：
[289] 查看整个问卷的统计
[290] 查看某一道题的统计
[291] 统计结果应该根据已经填写的数据自动生成。
